# pi-smart-compact — wayfinder map

Labels: wayfinder:map

## Destination

A validated, hand-off-ready **spec** for `pi-smart-compact`: a publishable pi extension in which a pluggable decision-model backend (Jev-shape: hosted Jev, Cloudflare Clef, self-hosted) classifies every compactable message — per a configurable message-type matrix — as **keep-verbatim / summarize / drop**, with a targeted, configurable LLM summarizing only the "summarize" class. Native pi triggers untouched; the same pipeline covers branch summaries. Validated by a thin prototype against real backends with measured numbers. Done = another agent or human can build the extension from the spec without re-deciding anything.

## Notes

- **Domain**: pi extension (TypeScript), pi ^1.0.2 (context_edit omissions need >= 0.87.1; compaction-hook API identical 0.85.1<->1.0.2 — see ticket 01). Local pi docs: `/home/linuxbrew/.linuxbrew/lib/node_modules/@earendil-works/pi-coding-agent/docs/` — `compaction.md` and `extensions.md` are the canon; prefer them over the web for pi behavior. Source: github.com/earendil-works/pi.
- **Hard constraint**: sessions are append-only; the kept region (`firstKeptEntryId` onward) always reaches the model verbatim. Decision power = (a) shape the summarized region, (b) move the cut point, (c) encode decisions inside the summary text. `session_before_compact` returning `{compaction}` fully replaces the native summary — no double compaction; returning nothing = native fallback.
- **Standing decisions (charting grill)**: native triggers only (no veto, no proactive prune, no extension-initiated compaction); pluggable Jev-shape backend (one wire format, per-provider envelope adapter, per-backend threshold profiles); decision scope = every message type behind a configurable type-x-action matrix; targeted-LLM summarizer, model configurable (default = session model); branch summaries in scope; publishable package in scope.
- **Skills**: HITL tickets -> /grilling + /domain-modeling; spike -> /prototype; library API facts -> context7-docs.
- **Credentials policy**: backends auth via env vars from gitignored `.env.local` (`FREEJEV_API_KEY`, `OPTOLLM_API_KEY`); never committed, never printed; **rotate both after the spike**. Delivered and verified — see ticket 05.
- **Verified mechanics** (research, see tickets): `ctx.compact()` exists (fire-and-forget) on ExtensionContext; `serializeConversation` truncates tool results at a hardcoded 2000 chars; TypeSafe signups currently paused — the live Jev leg is **freejev** (model `typesafe/jev-1.13-20260917`, hard 1 req/min → smoke tests only), the live Clef leg is the **optollm gateway** (`/v1/systemone`, model `clef`) for measured runs, and Ollama self-host needs no key (offline fallback). Spike-verified (ticket 06): no LLM API on ExtensionContext — use `modelRegistry.getApiKeyAndHeaders` + pi's exported `generateSummaryWithUsage` for the targeted summary; clef via optollm enforces 2–26 choice candidates; freejev rejects requests without an idempotency key; RPC mode drives compaction headlessly (`{"type":"compact"}` on stdin).
- **Prior art** (studied at charting): `@lienat/pi-jev-compaction` (pre-filters tool pairs in the summarized region, keeps native summary), `pi-jev-compaction` unscoped (replaces summary with verbatim encoding; falls back on no key/small reduction/errors), `@riposta/pi-jev` (5-module decision layer; its prune works at tool_result, not compaction), upstream `fast-jev-compaction` (Claude Code plugin by tamaratran, MIT — origin of all three). **Jev** = TypeSafe "System One" decision model: `{model, state, questions}` -> answers with probability distributions + confidence; types `noul`/`choice`/`score`; <=20 questions/request; ~0.2s. **Clef** = Cloudflare open-weight Jev-compatible (`clef` 27B, `clef-flash` 9B; <=64 q/req; REST envelope wraps answers in `{success, errors, result}`; images supported, irrelevant here).

## Decisions so far

- [pi compaction internals verification](issues/01-pi-compaction-internals.md) — on pi 1.0.2 the hook result `{cancel?, compaction?}` fully replaces the native summary (persists `fromHook: true`); `context_edit` omissions CAN drop kept messages from context append-only (architecture-expanding); `ctx.compact()` exists; pin ^1.0.2.
- [decision backend matrix (Jev / Clef)](issues/02-decision-backend-matrix.md) — one wire shape, tiny per-provider adapters; `jev-1.13.0` $0.042/M input (official API has NO 20-question cap; signups paused), clef/clef-flash 64 q/req $0.24/$0.09, Clef truncates over-limit state while Jev errors; recommend `DecisionClient.decide()` + fail-open to native.
- [self-hosted Clef serving](issues/03-clef-selfhost-serving.md) — realistic: Ollama serves clef/clef-flash natively on `/v1/systemone` (one command, 11–18 GB); transformers needs a ~20-line adapter; vLLM/generic endpoints cannot reproduce the decision head; Q4 GGUF fits 8–24 GB GPUs (accuracy unverified).
- [question design inventory](issues/04-question-design-inventory.md) — proven patterns: ask call and result separately; noul for branches, score for spectra, choice for escape-hatch paths; 8-stage state-fitting ladder to 25k tokens; batch by request-token budget; uncertainty -> do-nothing; thresholds + QUESTIONS_VERSION-style invalidation live in config.
- [backend credentials for the spike](issues/05-backend-credentials.md) — both legs live and smoke-tested: freejev fronts Jev (`typesafe/jev-1.13-20260917`, hard 1 req/min → smoke only); the firm "Clef grant" is the optollm gateway serving clef natively on `/v1/systemone` — no Cloudflare or TypeSafe keys needed; keys in gitignored `.env.local`, rotate after the spike.
- [thin spike: decision-driven compaction end-to-end](issues/06-thin-spike.md) — pipeline works: clef −97.8% / freejev −98% region reduction; decision p50 1.1s (clef); drops 5/5 identical cross-backend; 3/3 injected failures fail open to native; friction: single-action matrix rows must be policy (clef caps choices at 26 via optollm), freejev requires idempotency-key, serialize truncation bounds verbatim keeps at 2k chars. Prototype on branch `spike/thin-spike`.
- [decision matrix shape and defaults](issues/07-matrix-shape.md) — decision unit = block-cluster (assistant turns split into thinking/text/tool-call; six axes = six rows); row = allowed-action subset, singleton = pinned policy, never asked; hardcoded repair `call := min(call, result)`; action = argmax ∩ subset, below the backend `confidenceFloor` → keep (values = ticket 12); v1 Safe-table defaults (user/previous-summary/unknown pinned, assistant-text keep-or-summarize, thinking summarize-or-drop, tool-call keep-or-drop, tool-result full set); policy in config, judgment in code, invalid config fails loud to native.
- [fallback ladder + observability surface](issues/08-fallback-observability.md) — one rule: any pipeline failure → native, `{cancel}` never (re-trigger loop risk); rungs in order: no-key pre-flight (warn-once per session), transport (no in-hook retry), malformed (per-unit salvage, missing→keep), summarizer failure (→native), too-small reduction (`minReductionPct` default 50 → native); shadow ships in v1 (`mode: live|shadow|off`, default live, decisions-only — summarizer skipped); **no commands** (pi-jev's explain/trace/stats trio dropped) — surface is one-line outcome toast per compaction + passive JSONL telemetry, identical schema live/shadow, at `$PI_CODING_AGENT_DIR/smart-compact/telemetry.jsonl` (ticket 12's calibration input); no budget knobs (batching bounds cost to ≈1 request/compaction; idempotency key = content-hash + attempt).
- [branch summary pipeline](issues/09-branch-summary-pipeline.md) — the branch pipeline IS the compaction pipeline on `session_before_tree`: same matrix/defaults/ladder/telemetry rung-for-rung ("drop" = omit from the injected summary only — no cut point, branch stays navigable); summarizer gets branch-shaped customInstructions (pi's Goal/Progress/Decisions/Next Steps format); `label: smart-compact`; `details` must replicate pi's native readFiles/modifiedFiles shape (pi drops file lists on fromHook summaries); `userWantsSummary=false` → pure no-op (no calls, no records — telemetry stays compaction-only so ticket 12's dataset matches the distribution it gates); toast tags `[branch]`, JSONL records carry `kind: compact|branch`.
- [kept-region control mechanics (research)](issues/16-kept-region-control-mechanics.md) — pi 1.0.2 verified: native cut = `keepRecentTokens` token window (20k default, user-configurable in settings.json; cuts never at tool results, overshoot-only); hook's `firstKeptEntryId` consumed verbatim, zero validation — cut-earlier (keep MORE) is safe, unknown id = safe keep-everything, pi recomputes `estimatedTokensAfter` itself; `keptMessages: N` clamp composes safely (unset = pi default, N=0 = no-op, N ≥ session = cancel); omissions reachable ONLY via boundary drafts, no compaction-time path; pi has no native message-count floor. Full note on branch `research/kept-region`.
- [kept-region omissions: v1 scope](issues/10-kept-region-omissions.md) — v1 ships the configurable kept region as a `keptMessages: N` clamp (newest N never asked/summarized/dropped/omitted — cut-earlier-only, composes over pi's native window; churn hazard documented: oversized N → per-turn compaction re-trigger); kept-region omissions = named v2 module, not v1 (async boundary-draft mechanism, silent failures, unvalidated on kept material — starts from the research branch, must respect the same buffer); ticket 08's never-cancel gains its one exception (N ≥ session → cancel).
- [privacy posture per backend](issues/11-privacy-posture.md) — the "per backend" framing dissolved: posture is ONE orthogonal config axis, independent of backend choice — `privacy: "full" | "redacted"`, default `redacted`; redacted = simple secret-pattern redaction on ALL egress text, both channels (decision state + summary requests), nothing excluded; no tiers, no pairing validation; matrix unchanged (no local-only concept — privacy never reaches the matrix); pattern list ships in code, ticket 15 folds it into the spec.
- [threshold & calibration model](issues/12-threshold-calibration.md) — `confidenceFloor` ships shared at **0.1** ("escalate only when the backend is guessing"; per-backend override, values earned from shadow telemetry, never shipped — clef's confidence encodes class identity, so higher floors delete its summarize class before they protect its 0.23 drop); confidences provably don't transfer across backends (same unit: clef keep 0.56 vs freejev summarize 0.03); recalibration is a docs-only recipe (shadow ≥50 → bucket by class → floor := drop-band min − ε → re-shadow confirm) with a fresh-log rule instead of question versioning; question text ships as `questions.default.json` + user override (ticket 07 amended); `minReductionPct` stays 50 shared, `0` disables, and doubles as the all-keep re-trigger loop guard.
- [summarizer output format](issues/14-summary-output-format.md) — hybrid composer, identical on both hooks: previous-summary **verbatim head** (keeps survive every compaction; `minReductionPct` guards doc growth → native collapses it) + native-format LLM section over the summarize class only (pi's own prompt emits it free; scoping line + forwarded `/compact` focus; no UPDATE-merge) + `## Kept verbatim` serialized keep-blocks with **orphan-only** drop markers (`call := min(call, result)` leaves exactly one orphan shape) + native file tags from pi's own `preparation.fileOps`; `details` = `{ readFiles, modifiedFiles, smartCompact }` both hooks; split turns compose one doc over `messagesToSummarize ∪ turnPrefixMessages`; reduction gate reads the context delta, not region→composed ratio (09 amended).
- [eval/benchmark plan for the spec's validation section](issues/13-eval-plan.md) — three required gates (reduction, sanity, fallback), decision latency recorded but ungated (backend-owned, timeout+fail-open already bound it); the spike's single 40k fixture is the whole validation set, numbers are single-fixture facts; thresholds: reduction ≥80% per backend, wrong-drop = 0 (human-blessable), fallback 3/3 → native; harness stays throwaway — spec is prose-only, linking `spike/thin-spike` as reference.
- [packaging and distribution](issues/17-packaging-distribution.md) — npm name `@andrewjacop/pi-smart-compact` (bare `pi-smart-compact` is taken by an unrelated active pi-compaction package; scoped keeps the title, collision-free); install `pi install npm:@andrewjacop/pi-smart-compact`, README claims flat "Requires pi ≥ 1.0.2" (host pi in peerDependencies as `*` per pi packaging docs); config split — knobs under a `smartCompact` key in pi settings.json (user+project layering free via `pi.getSettings()`, per-project overrides work, invalid config fails loud to native), question text global-only as bundled `questions.default.json` + user override file `$PI_CODING_AGENT_DIR/smart-compact/questions.json` (out of settings.json by user decision, no project layering); key docs assemble from ticket 05 unchanged; problem-first README outline (10 sections) fixed as ticket 15's shell.
- [assemble the hand-off spec](issues/15-assemble-spec.md) — **the destination, reached**: `SPEC.md` at repo root, assembled from tickets 01–17 with every section traced to its decision (architecture, pipeline, matrix, backends, composer, kept region, fallback/observability, branch, privacy, validation, packaging); the concrete default question text was drafted at assembly from ticket 04's patterns (overridable config — execution, not policy). No open tickets remain; the map is complete and the build is the next effort.

## Out of scope

- **Per-tool override rules in the matrix**: the map's one fog item, never graduated — user deferred it at charting ("msg-type matrix only for v1"), and the destination (v1 spec, ticket 15) stopped before it; a clean v1.x candidate for a fresh effort.

- **Extension-initiated smart trigger** (decision model chooses WHEN to compact): ruled out at charting — v1 keeps pi's threshold/overflow/manual triggers. Research later verified `ctx.compact()` makes it feasible — a clean future effort, still out of scope here.
- **Building the production extension**: this map produces the spec only; the build is the next effort, handed the spec.
- **Decision-driven kept-region omissions (the "v2 module")**: named in the spec per ticket 10, worked as a separate effort — it needs its own validation of decision quality on kept-region material and its own failure-surface design; the map's destination (v1 spec) stops before it.
